## 1. Outcome and success definition

Deliver a buildable Windows 11-only WPF solution on .NET 10 that proves the architectural baseline: CommunityToolkit.Mvvm + Microsoft.Extensions.Hosting/DI + WPF-UI as primary Fluent foundation, with central package management, SDK policy, analyzers/formatting, license handling, one minimal runnable app (with a WPF-UI integration prototype path), one smoke test, ADRs for load-bearing choices, and a reproducible performance-baseline method.

Measurable success: fresh-clone `dotnet restore && dotnet build -c Release && dotnet test` passes on Windows 11 with only .NET 10 SDK; the minimal app launches to a window; `docs/DEPENDENCIES.md` + license inventory exist; `docs/PERFORMANCE.md` contains the first measured startup/memory numbers (not estimates); `docs/releases/0.1.0-report.md` records exact commands and evidence.

## 6. Design and architecture

- **Dependency boundaries (0.1.0):** one app (`DevTemWpf.App`) + two test assemblies. No `*.UI` / `*.Windows` / `*.Services` libraries yet — creating them now would be speculative abstraction (protocol §7). Boundaries are documented in ADR-0003 as the future split, but only the app exists.
- **Composition root:** `App.xaml.cs` builds `IHost` (`Host.CreateApplicationBuilder`), registers `MainViewModel` + `MainWindow`, starts host `OnStartup`, stops gracefully `OnExit`. No service-locator; no code-behind business logic (window lifecycle + host wiring only).
- **WPF-UI seam:** reference the `WPF-UI` package directly in the app; load theme via `Application.Resources` merged dictionary in `App.xaml`; wrap any version-sensitive access behind a tiny internal `ThemeBootstrap` static class so 0.3.0 can replace it with the token layer without touching ViewModels. Default to the opaque/static theme — no transparency or backdrop API calls in 0.1.0.
- **Configuration:** `appsettings.json` (optional, copied if present) + environment variables via the default builder; typed options pattern demonstrated with a single `AppOptions` record (window title/size defaults) to prove the pattern without building the full settings system.
- **Async/lifecycle:** `OnStartup` awaits `host.StartAsync()`; `OnExit` awaits `host.StopAsync(TimeSpan)` + `host.Dispose()`; ViewModel command is `IAsyncRelayCommand` with cancellation plumbed but trivially completed.
- **Resource impact:** one merged dictionary + one window + one ViewModel; no hidden sample content loaded at startup (protects the 0.1.0 perf baseline from pollution).
- **Scaffold contract stub:** clean = this minimal app minus WPF-UI if unselected (to be proven in 0.8.0); recommended/full = supersets. 0.1.0 only defines the contract text, it does not build the generator.

## 10. Performance plan and budgets

- Metrics (0.1.0): cold start (process launch → `MainWindow.ContentRendered`), working set after 5s idle. Navigation/scroll/animation metrics are N/A (nothing to navigate yet) — stated, not hidden.
- Reference hardware: this machine (document exact CPU/RAM/GPU/disk + OS build 26300 + SDK 10.0.401 in `PERFORMANCE.md`). Low-spec reference env (lower-power CPU, 8 GB, iGPU, SSD per roadmap) is identified as a requirement from 0.2.0 onward; 0.1.0 records that it has exactly one data point.
- Procedure: Release build, 5 cold launches after reboot-cache settle (or documented warm-cache alternative), median + max reported; working set via `Get-Process` sampled at 5s idle. Script-assisted, results pasted into `PERFORMANCE.md` — estimates forbidden.
- Budgets: provisional only (e.g. note "cold start < 2s on modern HW, working set < 150MB" as hypotheses to confirm). Ratification gate ≤0.4.0 per roadmap; this plan does not ratify.

## 11. Accessibility, resilience, and fallback plan

- 0.1.0 surface is one window + one button + one text element: verify keyboard Tab reaches the button, Enter activates it, focus is visible with default WPF-UI theme; automation name set explicitly.
- Theme fallback: opaque default; if the WPF-UI dictionary fails to load, app still opens with system theme + a logged warning (no crash, no empty window). No transparency/backdrop APIs called.
- Reduced-motion: N/A (no animations shipped) — recorded as such; the motion-fallback contract starts in 0.5.0.
- DPI/resize: window opens at 800×600, resizes without clipping the single control; check at 100% + 150% scale on the dev machine, screenshots optional.
- Errors: host start failure shows a message box + non-zero exit; no catch-all swallowing (log to stderr/debug, rethrow policy documented).

- No remote is configured: implementation checks `git remote -v`; if empty, work stays local and the report says "Not pushed — no remote configured" (truthful per protocol §12, not a failure).
- Push/MR/merge only if a remote with policy appears mid-milestone AND all AC gates pass; never bypass protections, never force-push, never rewrite history.
- Tag/release: `v0.1.0` tag only after the full gate (AC01–AC08) passes from the final candidate commit; GitHub Release only if remote + permissions allow; 0.x marked prerelease per protocol §11.3. If any gate is red or unverifiable, version is `Blocked`, no tag.
