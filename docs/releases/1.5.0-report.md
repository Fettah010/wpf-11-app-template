## 1. Delivered outcome

The `0.5.0` motion service is audited and extended into a coherent token +
primitive + lifecycle system, and the Effects page becomes a real, per-effect
showcase. Motion now has five predictable profiles (`Auto`/`Balanced`/`Rich`/
`Reduced`/`Off`), one reusable cancelable primitive per interaction (enter,
exit, selection, expand/collapse, feedback, reduced-motion-aware page
transition), and a shared `MotionScope` that stops tracked animations on
navigation-away, unload, theme change, deactivation, and shutdown. Effects are
opt-in, backdrop-only, and never touch text or interactive subtrees; the
water-warp technique was assessed and is **no-go** for a 1.5.0 shader (a
simulated prototype ships instead, off by default with a static fallback).
Everything is additive: no new packages, no breaking public API, no
persisted-enum renumbering.

## 2. Water-warp go/no-go decision (AC04)

**Decision: NO-GO on an HLSL shader in 1.5.0 — deferred (D13); ship a simulated,
backdrop-only distortion prototype instead.**

Evidence considered (dated in the plan §3):

- `ShaderEffect`/`PixelShader` load **bytecode only**; WPF targets shader model
  <= `ps_3_0`, so the build needs an external `fxc.exe` step (the legacy
  `PixelShaderCompile` MSBuild task is gone) plus packaging the `.ps` as a WPF
  `Resource`. That adds a Windows-SDK toolchain dependency to the build.
- Any `Effect` forces an **intermediate render target**, which **disables
  ClearType** (grayscale AA) for text in the affected subtree; the only safe
  use is a backdrop-only layer with no text/interactive content inside.
- Roadmap §8.5 gate conditions 1/5 require low-spec (8 GB reference) proof;
  there is no such machine here (D10/D27), and a software render tier cannot
  run the shader at all.

Shipped instead: a decorative, backdrop-only radial-highlight drift
(transform / opacity / radial-gradient driven), off by default, independently
switchable, with an identical-layout static fallback. It never becomes a
Clean-preset or startup dependency. Revisit with real 8 GB hardware and a
decided `ps_3_0` toolchain.

## 4. What changed

- **Tokens** (`Services/MotionTokens.cs`): stagger, exit distance, opacity/scale
  values, and named easings — one source of truth, no view-level magic numbers.
- **Profiles** (`MotionMode.cs`, `MotionPolicy.cs`): `MotionMode.Balanced = 4`
  appended (persisted values untouched); `EffectiveMotion` renumbered to
  richness order (`Off=0, Reduced=1, Balanced=2, Full=3`) — derived, never
  persisted; `Auto` settles on **Balanced** (tier/OS permitting); ADR-0016.
- **Primitives** (`IMotionService`/`MotionService`): `PlayExitAsync`,
  `PlaySelectionAsync`, `PlayExpandAsync`/`PlayCollapseAsync`,
  `PlayFeedbackAsync`, `PlayPageTransitionAsync(element, forward, ct)`; every
  method is policy-gated, cancelable, and snaps to final state on
  cancel/Off/exception.
- **Lifecycle** (`Services/MotionScope.cs`): `Register`/`StopAll` (reverse
  order, re-arms) / `Dispose`; wired into the shell
  (Deactivated/Closing/theme change) and the Effects page loops. No
  `CompositionTarget.Rendering`.
- **Effects** (`EffectsViewModel`, `EffectsPage`): master plus per-effect
  switches bound live to settings, warp fallback status, presets, and
  (development builds only) the resolved tokens/tier; new additive settings
  fields.
- **Docs**: `motion.md` (profiles, primitives, lifecycle, accessibility),
  `frozen-surface.md`, ADR-0016, `docs/DEFERRED.md` (D13 no-go), README,
  CHANGELOG, screenshots.

## 10. Known issues and deferred work

- **Animated-loop CPU not isolated.** `eng/measure-motion.ps1` measures idle
  CPU at the shell (all profiles 0%); the ripple/gradient/warp loops run only
  while the Effects page is open, and their incremental CPU cost was not
  separated from the shell baseline. The lifecycle guarantee (loops stop on
  unload) is covered by unit + UI tests; a dedicated animated-CPU sampler is a
  possible follow-up but is not required by the milestone's budgets.
- D13 HLSL water-warp shader remains deferred (no-go this milestone).
- D10/D27 (8 GB reference machine) remain open — proxy evidence only.
- D09r visual regression stays **advisory** (VR advisory CLEAN at 0% here).
