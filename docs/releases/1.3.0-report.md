## 3. Research and architecture decisions

- **TimePicker NO-GO** (T02): renders (screenshot) but exposes no automation name and credible broken-popup reports exist on exactly 4.3.0. Gallery-scoped composite (validated hour/minute + Now) instead. No new dependency, no second theme suite. ADR-0014 records the lookup strategy below, not the control.
- **Strings.OverrideCulture** (T08 root-cause fix): page construction ran on threads whose `CurrentUICulture` never saw `ApplyCulture` (proven: same managed thread id read `de` at MainViewModel construction and `en-US` at page construction), so x:Static content silently fell back to English while VM lookups were German. Resx lookup now prefers an explicit startup-set culture; `CultureService` sets all four culture slots, applied before host build and re-asserted on the dispatcher. See ADR-0014.
- **No reload-on-navigation** (T04): a 300 ms reload raced filter/edit gestures; the grid loads eagerly, refresh stays explicit.
- **HasResults vs IsEmpty** (T04): with `CanUserAddRows`, `NewItemPlaceholder` keeps `ICollectionView.IsEmpty` false forever — emptiness derives from data-row count. Unit suites can't catch this (no placeholder without a grid), hence the UI round-trip test.
- **Native DataGrid/TreeView + WPF-UI styling** (no new suite); **recipes over controls** for paging/selectable-cards (documented).
- **Chart rebinding** (not mutation): new Series/Axes objects per theme change; unsubscribe on navigate-away (transient VM vs singleton settings).
- **Sample data stays English** (metric labels, activity rows, tree labels, Ada/email/42): chrome localizes, dataset doesn't — documented rule. Weekday axis labels are culture-aware day names (real i18n, not resx).
