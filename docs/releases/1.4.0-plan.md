## 1. Outcome and success definition

The template supports four real application shapes — Sidebar, Rail, Top-navigation,
and Tabbed document-workspace — sharing one navigation contract, while keeping
navigation lifecycle understandable and every interaction keyboard-reachable.
Success = each shell preset is selectable at scaffold time and independently
smoke-tested; no stale async work touches a page after cancellation/disposal in
race tests; workspace persistence has a documented recovery contract; and
drag-and-drop ships only if its prototype passes the accessibility,
reliability, and performance gates (otherwise it stays documented as deferred).

## 6. Design and architecture

- `ShellMode` extended: `Sidebar = 1` (unchanged default), `Rail = 0`
  (unchanged), `Top = 2`, `Tabbed = 3`. `MainViewModel.MapMode` gains Top;
  Tabbed keeps `LeftMinimal` rail chrome with the frame content replaced by
  the workspace host. `SettingsViewModel.ShellOptions` lists all four.
- Route registry (`Services/NavigationRoutes.cs` or equivalent, UI-free and
  unit-tested): stable string keys per page (`home`, `dashboard`, `controls`,
  `data`, `tokens`, `effects`, `diagnostics`, `settings`), title + page type +
  symbol; single source for nav items, palette entries, and workspace
  documents. Page/VM implementations reused across shells without rewrites.
- Workspace (`WorkspaceViewModel` + workspace host in Tabbed shell):
  `OpenDocument(key)` focuses existing or opens new (async factory with CTS);
  each open carries a generation token — completions from a superseded
  generation are ignored (the 1.3.0 stale-update lesson made structural).
  Close disposes (`OnNavigatedFromAsync` + CTS cancel). Selection syncs to
  rail. State persisted to `ShellSettings` (new additive `WorkspaceState`
  property: open keys + selected key + split sizes); malformed/stale state →
  safe default (home document), never a startup failure.
- Command palette: Ctrl+K (and palette button) opens an overlay listing
  route commands (stable IDs `nav.*`) + shell actions (`shell.switch.*`);
  filter-as-you-type substring; Up/Down/Home/End/Enter/Esc; disabled items
  announced but not executable; shortcuts displayed; invoking focus returns
  to the invoker on close. Names localized via `Strings` (automation names
  invariant per the 1.3.0 rule).
- Drag-drop (prototype-gated): internal tab reorder with a private
  `DataObject` format (`DevTemWpf.DocumentTab`), drop indicator, keyboard
  alternative (`Move Left/Right` commands, Alt+Arrow); `GridSplitter`
  detail split with persisted proportions. No OS/file drops, no tear-out.
- Template: `Shell` choice parameter (`Sidebar` default) seeds the generated
  default shell (replacement into generated seed config; presets unchanged).
  All shell code ships in every scaffold by design — shells are runtime modes
  of one adaptive shell, so the "no unselected shell files" rule is satisfied
  structurally and asserted per shell-preset in the matrix (no broken
  navigation references in any generated app).
- Residue rule: no shell-specific sample/package leaks; `NoChartLeakTests`
  pattern extended if new module-adjacent files appear (none expected).

## 11. Accessibility, resilience, and fallback plan

- Top nav: full keyboard reachability, visible focus, automation names on
  every nav item (invariant rule), theme/high-contrast verified.
- Tab strip: tabs are keyboard-focusable, closable via keyboard
  (Ctrl+W and/or Delete command), reorderable via keyboard alternative;
  selection announced; overflow scrolls without clipping required controls.
- Palette: keyboard-complete (open/filter/move/execute/dismiss), correct
  initial focus, Esc dismissal, focus return to invoker; names + roles
  meaningful; usable with reduced motion (instant open/close path).
- Drag-only interactions always have keyboard/menu equivalents (AC05).
- Reduced motion: shell switches and palette respect the existing motion
  policy (instant path under Reduced/Off); no new perpetual animations.
- Resilience: corrupt/missing/stale workspace + settings files → safe
  defaults, startup never fails (existing `LoadAsync` catch-all extended to
  the new state property); unknown future enum strings → defaults.
- DPI/resize: Top + Tabbed verified at 640–1600 px widths and 100–200%
  scales; narrow-window collapse rule preserved for left-pane modes.

## 18. Mid-version adjustment record (2026-10-16, T03)

**Change:** runtime shell hot-switch replaced by restart-apply (persist now,
apply at next launch), recorded in ADR-0015.

**New evidence:** 15+ UI-automation runs switching Sidebar→Top through the
real Settings UI crashed the app intermittently (`DoubleAnimation` NaN
destination during template teardown). WPF-UI 4.3.0 source inspection
(`NavigationViewCompact.xaml`: `PaneOpen` animates `PaneGrid.Width` with
`To="{TemplateBinding OpenPaneLength}"`) plus upstream PR #1012/#1015
(fixed only the load path) explain it. Four mitigations exhausted with
evidence: close-first + 500 ms settle; transitionless close + Width
defuse; control recreation with unbind-first (tracing proved the crash
precedes replacement — binding-driven trigger). Launching directly into any
persisted shell never crashes.

**Impact:** T03/T04 UI tests drive switches via persist + in-app Restart
button + relaunch attach; AC01–AC04 verification unchanged (all shells
selectable at scaffold time and independently smoke-tested; no stale async
updates; persistence/recovery contract tested); drag gate (AC05) unaffected.
Same milestone, no scope expansion, no public-contract change beyond the
already-planned additive `Shell` parameter.
