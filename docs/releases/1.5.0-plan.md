## 1. Outcome and success definition

Motion and effects feel more deliberate and premium **without** turning the
default application into an expensive effects demo. Success = the existing
`0.5.0` motion service/policy is audited and extended into a coherent token +
primitive system with a per-effect showcase and measurable, cancelable,
reduced-motion-safe behaviour; a water-warp/distortion prototype produces a
recorded **go/no-go** decision backed by measurements and a reliable static
fallback; `Auto`/`Balanced`/`Rich`/`Reduced`/`Off` behave predictably; no
effect enters the Clean preset or the startup path; and `v1.5.0` ships with all
existing gates green.

## 6. Design and architecture

- **Layering.** All motion code stays app-level (`src/DevTemWpf.App/Services`)
  in 1.5.0; extraction into `DevTemWpf.UI` is a 2.0 concern (roadmap §9.0/N02).
- **Tokens.** `MotionTokens` gains stagger interval, a small set of standard
  offsets, and named easing factories reused by every primitive; no magic
  numbers in views.
- **Profiles.** `MotionMode` appends `Balanced = 4`; `EffectiveMotion` appends
  `Balanced = 3`. `MotionPolicy.Resolve`: Off→Off; Reduced→Reduced;
  Full→Full (Rich); Balanced→Balanced; Auto→ Reduced when OS animations are
  off or render tier ≤ 0, else Balanced. (Rich remains reachable explicitly.)
- **Primitives.** New `IMotionService` members built on one `Storyboard` per
  dependency property (no multiple writers): `TransitionAsync`,
  `PlayEnterAsync`/`PlayExitAsync`, `PlaySelectionAsync`,
  `PlayExpandAsync`/`PlayCollapseAsync`, `PlayFeedbackAsync`; every method
  accepts a `CancellationToken` and snaps to the final state on cancel/exception.
- **Lifecycle.** `MotionScope` (`IDisposable`) tracks animations for a view;
  `StopAll()` on navigation-away/unload/theme-change/deactivation/shutdown.
  No `CompositionTarget.Rendering` subscription is left after a page leaves the
  tree.
- **Effects boundary.** The simulated distortion is a backdrop-only decorative
  layer (no text or interactive controls inside the effect subtree), so
  ClearType/input are unaffected (evidence §3). It reads a single
  `EffectsEnabled`/per-effect setting and the resolved policy; disabled ⇒ a
  static backdrop visual with identical layout.
- **Compatibility.** `ShellSettings` gains only additive per-effect boolean
  fields (and the appended enum member); unknown/missing fields keep working;
  a settings round-trip test guards it.
- **ADR.** ADR-0016 "Motion profile model, primitives, and effects policy"
  records the profile semantics, single-writer rule, MotionScope lifecycle, and
  the water-warp go/no-go (shader deferred with toolchain/ClearType/tier evidence).

## 10. Performance plan and budgets

- Reference: proxy machine (MSI MS-7E28, Ryzen 8700G, 32 GB, 2560×1440,
  build 26300.9711). **No 8 GB reference machine** (D10/D27) — all results are
  proxy/provisional; the water-warp low-spec gate (conditions 1/5) cannot be
  satisfied and is reported as such.
- Procedure: `eng/measure-startup.ps1` (startup/WS) + a new animation-cost
  sampler run at each profile; medians of ≥5 runs with range; idle CPU over 30 s.
- Budgets (carry-over unless ratified otherwise): startup ≤ 1.2 s; working set
  ≤ 150 MB; idle CPU ~0%; no unbounded memory growth across 50 cycles; the
  prototype must not raise idle CPU above ~0% when disabled/static.
- Fallback expectation: with the effect disabled, metrics must match the 1.4.1
  baseline within noise.

## 11. Accessibility, resilience, and fallback plan

- Keyboard/focus/automation names unchanged; every primitive cancelable and
  snap-to-final on error; effects off text/interactive subtrees so ClearType,
  hit-testing and readability are unaffected (evidence §3).
- Reduced motion (OS + setting) and high contrast force static behaviour;
  effect switches are independent; `Off` ⇒ instant, no storyboards.
- Window deactivation / theme change / shutdown stop tracked animations;
  no persistent `CompositionTarget.Rendering` after unload.
- Fallback: if any effect fails, the static backdrop renders with identical
  layout; motion exceptions never crash a view (existing contract retained).

## 14. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Profile default change (`Auto`→`Balanced`) surprises users | Explicitly recorded as a roadmap-authorized refinement; `Rich` remains one click away; documented in CHANGELOG |
| Duplicate animation writers on one DP | Single-`Storyboard`-per-property rule; `MotionScope` ownership; review + tests |
| Leaked animations/timers after navigation | `MotionScope.StopAll` on navigation/unload/theme/deactivation; UI no-leak test; idle-CPU check |
| Prototype effect raises idle CPU or hurts text clarity | Backdrop-only, off by default, static fallback; text outside effect; measured at all profiles |
| Visual checking is flaky/occluded | Deterministic PrintWindow harness; checks target solid regions/tokens, not text; thresholds documented |
| No 8 GB machine blocks the shader gate | Report proxy-only evidence honestly; defer the shader (no-go) rather than waive the gate |
