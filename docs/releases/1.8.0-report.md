## Delivered scope

Only the compiled design-token resources move behind `DevTemWpf.UI`.
ADR-0020 records the independently demonstrated boundary and defers Windows
and service-library splits until each has a real second consumer. The app
remains the composition root, and the migration draft maps the 1.x template,
resource, settings, and DI contracts.

The package-only consumer restores the built UI `.nupkg`, resolves Comfortable
and Compact spacing resources, switches density at runtime, builds without a
gallery project reference, and launches. The generated-template package
includes a NuGet package README and preserves the existing app and item
template contracts.

The template Full-preset smoke exposed a race in which queued progress
callbacks could overwrite the completed download state. `UpdateService` now
ignores callbacks after the download leaves the `Downloading` state and sets
the terminal progress after the state transition. A queued synchronization
context makes the regression test deterministic. The focused regression and
the full Release suite pass.

## Performance and limitations

On Windows 11 Pro build 26300 with an AMD Ryzen 7 8700G and 31.1 GB visible
RAM, five startup runs measured a 0.85 s median / 1.34 s maximum for the
v1.6.0 baseline and a 0.86 s median / 0.89 s maximum for the prototype.
Working-set medians/maxima were 137.2/137.4 MB and 137.2/137.3 MB,
respectively. Published output increased by 49,617 bytes (+0.043%); the
prototype UI package is 6,824 bytes. These are proxy measurements, not proof
of the 8 GB reference-machine budget. Visual Studio's interactive XAML
designer was not available for automated verification.

## Release status and blockers

- The release workflow is active on `main` and uses GitHub-hosted Windows
  runners; it does not depend on the user's PC. Its first default-branch
  preflight failed closed at the source template residue check. PR #11 fixes
  that failure; hosted CI and a new default-branch preflight must pass before
  a candidate is pinned or v1.8 is published.
- The scheduled job is best-effort UTC cron and cannot guarantee an exact
  start time. It pins a verified candidate, reruns the release gates, and
  publishes only after all checks pass. No user's PC is required.
- PRs [#8](https://github.com/Fettah010/wpf-11-app-template/pull/8) and
  [#9](https://github.com/Fettah010/wpf-11-app-template/pull/9) are merged;
  v1.7.0 is published. The v1.8 timed release remains fail-closed pending a
  successful hosted preflight and candidate pin.
