## 1. Outcome and success definition

`dotnet new devtemwpf-app` generates a standalone, named application in
Clean/Recommended/Full presets (plus shell/theme/tests options) that
restores, builds, tests, and launches with no placeholders, absolute paths,
or dead features. Item templates scaffold pages and services by convention.
Template matrix is machine-verified by `eng/test-templates.ps1`.

Measurable success: all supported combos generate + build + test + launch;
`#if`/exclusion mechanics proven; item templates verified; docs published.

## 3. Research questions, evidence, and analysis

| Question | Options | Evidence and checked date | Finding | Decision and impact | Validation |
|---|---|---|---|---|---|
| Conditional content | `#if` comments vs file copies | Empirical spike (2026-10-14, SDK 10.0.401): `//#if (bool)`/`//#else`/`//#endif` in `.cs`, `<!--#if … -->` in `.xaml`, computed `type:computed` symbols, `sources.modifiers[].condition+exclude`, `sourceName`, `preferNameDirectory` — all verified by generating both variants | Directives are inert comments in repo builds; engine processes at instantiate | Single tree (`src/` + root `template.json`); `#if` regions only where presets diverge; conditional excludes for module files | TemplateSmoke builds every preset |

| Per-service flags | Full matrix vs preset bundles | Combinatorial coupling (dashboard needs favorites; diagnostics needs services) explodes the verified matrix | Presets bundle coherently; per-service flags deferred with mechanism proven | Symbols: Preset/IncludeTests; computed IncludeDashboard/Diagnostics/Services; per-service flags → DEFERRED (0.9.0 candidate) | Matrix = presets×tests |
| Item templates | Page/service/VM/test | Engine supports item templates (same schema, `tags.type: item`); VS Add-Item dialog does NOT surface them (MS documented) | `devtemwpf-page` (Page+XAML+VM+registration checklist comment), `devtemwpf-service` (interface+impl+registration comment); CLI-verified | Two item templates, tested by instantiation | TemplateSmoke instantiates both |
| VS integration | VSIX now vs later | CLI templates surface in VS Create-Project automatically once installed (MS documented); custom VSIX duplicates source | No VSIX in 0.8.0; document install-then-create flow | Note in template docs | Docs |
| Generated-app validation | Script vs xunit | Generation is process/orchestration work; xunit would shell out anyway | `eng/test-templates.ps1` (install → generate → rename-check → placeholder-check → restore/build/test/launch → module presence/absence → package-ref check); CI runs Clean preset, full matrix local + release | Machine-verified matrix | Script green |

## 6. Design and architecture

- **Single tree.** Template sources = repo files; directives are comments to
  compilers. `.template.config/` at root; install via
  `dotnet new install <repo-or-package>`.
- **Module map:** dashboard files + LiveCharts + SampleData + favorites +
  nav + composition lines (`IncludeDashboard` = Full); diagnostics files +
  nav + lines (`IncludeDiagnostics` = non-Clean); service files + packages +
  tray/logging/hook lines (`IncludeServices` = non-Clean). Localization,
  tokens, motion, feedback stay in all presets (zero-dep or core).
- **Generated-app contents:** src/**, tests/** (unless `--IncludeTests false`),
  `eng/smoke.ps1` (+measure), global.json, props, editorconfig, gitignore/
  attributes, LICENSE, appsettings, generated README + FEATURES.md.
  Excluded: docs/**, roadmap/protocol/CHANGELOG (repo history), .github/**
  (generated apps start CI-free; documented), bin/obj.
- **Naming:** `sourceName: DevTemWpf` renames namespaces, files
  (`DevTemWpf.slnx`), and content. `Wpf11AppTemplate` AppData dir stays
  (documented; rename-safe constant).
- **Item templates** live under `templates/items/*` with own template.json;
  excluded from the app template's sources.

## 9. Test and CI plan

- `eng/test-templates.ps1 [-Presets Clean,Recommended,Full] [-IncludeTests]`:
  per combo — install, generate to `%TEMP%`, residue/placeholder grep,
  module asserts, `dotnet restore/build/test`, launch check (reuse generated
  `eng/smoke.ps1`), cleanup temp. Full matrix at release; CI runs Clean.
- Repo suite must stay green throughout (annotations are comments).

## 10. Performance plan and budgets

- Startup budgets unchanged; generation time noted (not gated).
- Generated apps measured once (Full) to confirm parity.

## 11. Accessibility, resilience, and fallback plan

- Generated apps inherit shell/a11y work. Template failures (missing SDK,
  bad name) surface engine errors + troubleshooting guide.
- Script cleans temp dirs even on failure (try/finally); never touches repo.

## 12. Dependency, license, and security impact

- Zero new packages. Template warning honored: install only from trusted
  sources (our repo/package). Generated LICENSE/NOTICE ship (dependency
  list per preset in FEATURES.md).

## 13. Documentation and examples

- `docs/template/presets.md` (matrix + examples), `generators.md`,

## 14. Risks and mitigations

| Risk | Mitigation |
|---|---|
| `#if` syntax wrong for an extension | Proven for .cs/.xaml in spike; csproj verified in first smoke (Clean build) |
| `sourceName` over-replaces (e.g. inside URLs) | Grep generated tree for breakage; build proves |
| Matrix time explosion | CI runs Clean only; full matrix local + release-gated |
| Template install pollutes dev environment | Script uninstalls after run; prefix temp dirs `devtem-tmpl-` |
| Scope creep (per-service flags, VSIX, publishing) | §5; deferred with mechanism |
