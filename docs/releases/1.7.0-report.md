## 3. Research and architecture decisions

See ADR-0019. Key findings that changed the implementation:

- A single `--Namespace <App>.App` knob cannot serve test scaffolds (they live
  in `<Root>.Unit`). Replacing the whole `DevTemWpf` root solved both and made
  the flag one value instead of two.
- `replaces` on a derived symbol rewrites file *contents* but not file
  *names*; file names only follow `sourceName`. Companion files are therefore
  named `<SourceName>.Row.cs` / `.Item.cs` / `.Node.cs` so the name is unique
  per invocation while the class name still follows the derived transform.
  Verified with a scratch template before applying to the catalog.
- Template `forms` with `"identifier": "replace"`, `"pattern"`, and
  `"replacement"` is the supported way to derive names (`parameters` with
  `oldValue`/`newValue` is not; it silently produced identity output).

## 11. Reproduction and recovery instructions

```powershell
dotnet restore
dotnet build -c Release --warnaserror
dotnet test -c Release
powershell -ExecutionPolicy Bypass -File eng/test-generators.ps1
powershell -ExecutionPolicy Bypass -File eng/test-templates.ps1
dotnet pack templates/pack/DevTemWPF.Templates.csproj -c Release -o artifacts/packages
powershell -ExecutionPolicy Bypass -File eng/test-generators.ps1 -PackagePath artifacts/packages/DevTemWPF.Templates.1.7.0.nupkg
```

Both generator scripts use a throwaway `DOTNET_CLI_HOME`; if a run fails, the
work directory is kept and its path printed for inspection.
