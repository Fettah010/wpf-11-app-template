## Delivered in the working-tree candidate

- `SettingsService.LoadAsync` retains defaults recovery for missing files and
  malformed JSON, but propagates cancellation and other read failures. A
  locked-file regression verifies the unreadable settings file is unchanged.
- UI automation uses supported Invoke/SelectionItem patterns before click
  fallback and activates Settings before waiting for its shell selector.
- The generator test harness disables persistent MSBuild nodes, the MSBuild
  server, and shared compilation for isolated redirected child builds, then
  restores the caller's environment.
- Added the 1.9 migration/compatibility draft, deferred-work disposition
  register, support-policy wording, and refreshed dependency and performance
  records. The owner reviewed the inventory and dispositions under explicit
  authorization; candidate 2.0 contract decisions remain explicitly
  unapproved.
- Corrected `eng/test-templates.ps1` so displaying child-process logs cannot
  contaminate the helper's Boolean result and produce a success-shaped line
  after a failure.
- Added `eng/measure-large-list-effects.ps1` to capture a reproducible
  interactive 10k-row, keyboard-dispatch, individual-effect CPU, and switch
  latency profile while restoring user settings byte-for-byte.
- Set the template package metadata to 1.9.0 and verified the exact local
  candidate package before publication.

These local results do not replace hosted candidate checks.
An earlier clean-clone run found one intermittent generated
Full-preset keyboard-palette timeout (215/216); the failed test passed when
rerun alone (1/1), and the complete generated Full smoke rerun passed 216/216.
That investigation also found `eng/smoke.ps1` could continue after a failed
test step and print `SMOKE PASSED`. The script now throws on a failed native
step instead; a simulated exit-17 probe confirmed it stops without a success
message. The corrected full source and packed matrices, full clean-clone
build/test/UI suite, generated-app smoke matrix, packed generator gate,
package-only UI consumer, and shell-surface check all passed from the
corrected code commit above. The initial test failure remains recorded as
intermittent evidence.

On the first hosted candidate run, `build-test`, source shell/preset/module
shards, packed preset shards, and packed generator gate passed. The
`template-package-shells` job failed only on its Full/Tabbed smoke process
(exit 1 after 134.6 seconds); the same matrix's Recommended/Rail, Top, and
Tabbed and all Custom module builds passed. The failure tail misleadingly
showed `OK: Full smoke` because `Invoke-Native` allowed tailed log text into
its Boolean pipeline result. The logger now writes those lines to the host.
The exact packed Tabbed matrix passed twice locally, including after this
fix, but the hosted job must pass on a rerun; the underlying first-run
non-zero exit is retained as unexplained/intermittent, not dismissed.
