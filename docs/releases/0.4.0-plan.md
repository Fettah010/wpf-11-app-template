## 6. Design and architecture

- **No new assemblies** (ADR-0003 holds); gallery lives in the app until the
  0.6.0 dashboard forces the split question.
- **Services:** `ISnackbarService`/`IContentDialogService` singletons
  (WPF-UI impls); presenters attached in MainWindow ctor (view boundary);
  VMs call services (never controls) → unit-testable via fakes.
- **Busy pattern:** `IsBusy` + `IAsyncRelayCommand` (single-flight);
  demo button disables + ring shows; errors surface as text (no silent catch).
- **Validation:** `ObservableValidator`; validation runs explicitly on Save
  + live on property change (partial hooks call `ValidateProperty`);
  Save command `CanExecute` = `!HasErrors`.
- **Dialog result:** confirmation demo writes `ContentDialogResult` to a
  status line (proves the round-trip).

## 11. Accessibility, resilience, and fallback plan

- All demo controls named; focus ring default; disabled states legible;
  validation errors as text (not color-only); dialog buttons keyboard
  reachable (native ContentDialog behavior).
- Dialog without host → service throws (our host always set in ctor; noted).
- Snackbar queue overflow → upstream handles (replace-current); noted.
