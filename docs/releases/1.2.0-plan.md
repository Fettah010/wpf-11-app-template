## 1. Outcome and success definition

The reference app becomes the polished, coherent showcase the README
promises: one token-driven spacing rhythm across all pages (density switch
visibly changes it), consistent page headers and states, a gallery page with
a category index and complete state coverage, verified shell/dashboard
layouts at documented sizes and themes, and an honest visual-regression
spike with zero new packages. Success = every §8 acceptance criterion maps
to reviewed before/after screenshots, executed UI tests, or an explicit
research note — no decorative claim without evidence.

## 2. Current repository state and baseline

- `main` @ `9af2149`, clean tree, tags through `v1.1.0`; SDK 10.0.402 (patch drift from 10.0.401, harmless).
- 1.1.0 gates all green locally and remotely (85/85, UI 4/4 executed, both template matrices PASSED, perf 0.75 s / 144.2 MB proxy).
- Token layer (`tokens.md`, ADR-0007): colors fully tokenized (`App*` brushes, DynamicResource); typography tokenized; spacing **half-tokenized** — `AppContentMaxWidth`/`AppPageMargin`/`AppCardPadding` used everywhere, but `AppSectionSpacing`/`AppItemSpacing`/`AppControlSpacing` (Doubles) are referenced only by the TokensPage demo bars. All real page rhythm is literal `Margin="0,0,0,4/8/12/16"` / `"0,0,8,8"` / `"0,0,16,8"` (100+ occurrences across 7 Views). Density swap therefore changes almost nothing except card padding — the central 1.2.0 defect.
- Page chrome is consistent (ScrollViewer + `AppPageMargin` + `AppContentMaxWidth` on 5 pages; Home uses Margin variant; Dashboard uses unscrollable Grid + `AppPageMargin` — data-dense, justified exception).
- Controls gallery (ControlsPage) is a flat wall: sections with headings + partial usage notes, no category index, no anchor/keyboard navigation between sections; state coverage unverified against the §8.3 checklist (normal/hover/pressed/selected/disabled/focus-visible/invalid/loading/success/warning/error/empty).
- No visual-regression infra (D09r open); `eng/capture-screenshots.ps1` exists (dev-only, proven in 1.1.0) and is the capture foundation for the spike.
- Template surface frozen (`TemplateSurfaceTests`): no template.json changes in 1.2.0.

## 6. Design and architecture

- No architecture change: single app project, same DI, same template surface, same package set.
- Token design: four `Thickness` keys (names: `AppGapTitle` `0,0,0,4`/`0,0,0,4`?, `AppGapSection`, `AppGapItem`, `AppGapFlow`) — final values per density chosen at implementation so Comfortable matches today's rhythm and Compact tightens it (density switch must be screenshot-visible). `AppSectionSpacing`-family Doubles stay for scalar uses (demo bars, code-behind); document the Thickness-vs-Double rule in `tokens.md`.
- Gallery index: section-header buttons row (keyboard-focusable, automation-named) scrolling the page `ScrollViewer` to anchors + moving keyboard focus to the section target (focus return verified by UI test). No new routes/pages.
- Spike design: `eng/compare-screenshots.ps1 -BaselineDir docs/images/baselines -Tolerance <pct> -Mask <rects>`; captures via the proven topmost/maximize path; fails with a diff PNG artifact + changed-pixel %. Baselines: Home, Controls, Settings at 2560×1440 maximized, system theme. Dashboard excluded from pixel gate (volatile timestamps) — manual review only, documented.
- UI tests: `Resize_PreservesNavigationAndContent` (640/1024/1280/1600), `ThemeSwitch_LightDark_KeepsContent` (Settings selector round-trip). Both honor `RequireUiOrSkip` + launch maximize/focus.

## 10. Performance plan and budgets

- Same machine as 1.1.0 (MSI MS-7E28, Ryzen 8700G, 32 GB, 2560×1440, build 26300.9711): before-values 0.75 s / 144.2 MB / idle 0%.
- Ratified budgets: cold-start median ≤ 1.2 s; working set ≤ 150 MB; idle ~0%. Redesign must not regress beyond noise; any breach → fix or documented ratified exception before release.
- Proxy label retained (no 8 GB reference).

## 11. Accessibility, resilience, and fallback plan

- Gallery index fully keyboard-operable with visible focus + focus return; section targets have automation names.
- Theme round-trip (light/dark/system) must not lose content or focus; high-contrast usable (manual pass recorded; no blur/gradient-carried meaning).
- Reduced-motion paths untouched; density swap must not clip content at 640px min width (resize test covers structure; screenshots confirm).
- Corrupt-settings/density fallback behavior preserved (existing guards).
