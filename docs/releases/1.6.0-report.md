## 1. Delivered outcome

Production services become individually selectable, safer, better documented,
and more complete for Windows desktop applications (roadmap §8.6).
Named presets (Clean, Recommended, Full) remain byte-identical in output to 1.5.0;
the single coarse `IncludeServices` switch is replaced with per-module flags
(`IncludeLogging`, `IncludeLocalData`, `IncludeHttp`, `IncludeBackup`,
`IncludeUpdates`, `IncludeTray`), plus existing `IncludeDashboard` and
`IncludeDiagnostics`. Every module is reachable via a `Custom` preset with
`--Custom<Module>` switches and can be turned off completely (source files,
packages, references, DI registrations, configuration, and tests).

Key additions:
- **Logging privacy & boundedness (ADR-0018)**: `LogPrivacy` + `RedactingTextFormatter`
  mask secret-shaped tokens and Bearer credentials on every log line; file sink
  is capped at 5 MB with 14 retained files in addition to daily rolling.
- **Richer update UX (ADR-0014)**: Diagnostics displays installed vs available
  version, delta vs full indicator, explicit restart prompt (no unprompted
  auto-restart), Retry / Cancel, and an opt-in channel switch with explicit
  downgrade confirmation.
- **Harden backup/restore**: Typed `BackupException` / `BackupFailure`, atomic
  temp+move writes, entry-count and entry-size caps, duplicate entry rejection,
  and path-traversal prevention.
- **Optional auth sample (`--CustomAuth`)**: MSAL (`Microsoft.Identity.Client`
  4.91.0, MIT) public client + `IAuthService`; no client secret, no UI, silent
  cache-only restore at startup. Unconfigured ⇒ no network, no provider call.
- **Optional crash sample (`--CustomCrash`)**: Local-first, redacted crash capture
  (`ICrashReporter`, `ICrashSink` adapter seam) under `%LOCALAPPDATA%`; no vendor,
  no default telemetry. Reuses `LogPrivacy.Redact`.
- **Windows app notifications: NO-GO in 1.6.0 (deferred, D07t)**: Evaluated
  `AppNotificationManager` (Windows App SDK); interactive cold-start activation
  could not be verified headlessly and adds unmeasured runtime footprint; in-app
  Snackbar serves as the reliable fallback.
- **Distribution docs & tooling**: `docs/release/packaging.md` separates portable,
  Velopack, and MSIX profiles; `eng/pack-portable.ps1` produces portable zips with
  explicit signed vs unsigned reporting.
- **Guides**: Added `module-selection.md`, `updates-and-channels.md`,
  `backup-restore.md`, `auth-and-crash.md`.

## 2. Windows app notifications go/no-go decision (AC03)

**Decision: NO-GO on shipping Windows App SDK app notifications in 1.6.0 —
deferred (D07t); in-app Snackbar fallback ships as the primary notification path.**

Evidence considered (dated in the plan §3.1 & task T06):
- `AppNotificationManager` requires `Microsoft.WindowsAppSDK` (v2.5.1) runtime
  on the target machine, adding significant footprint to unpackaged apps.
- For unpackaged apps, COM server registration occurs via `Register()`, but
  interactive cold-start activation could not be verified headlessly in CI.
- App notifications fail silently for elevated (admin) desktop apps.
- Packaging/MSIX requirements necessitate manifest extensions (`windows.toastNotificationActivation`
  and `windows.comServer` with CLSID).
- The Clean preset must remain lightweight and zero-dependency; adding WindowsAppSDK
  conflicts with the 8 GB target baseline unless proven completely optional.

Shipped instead: the in-app Snackbar and feedback service serve as the default
reliable fallback. Notification architecture and unsupported modes are documented.

## 7. Accessibility, text clarity, and security review

- UI accessibility: Diagnostics page update controls (version comparison,
  channel selector, restart button, error notifications) provide full keyboard
  navigation, AutomationProperties names, and high-contrast support.
- Security review:
  - Secrets redaction: `LogPrivacy.Redact` eliminates bearer tokens, private
    keys, API keys, and connection strings from file sinks and crash dumps.
  - Auth sample: Strictly opt-in; no secrets embedded in source; uses MSAL
    public client flows with interactive/broker/silent tokens.
  - Crash sample: Strictly local-first; payloads written to `%LOCALAPPDATA%`
    with redacted fields; zero network transmission by default.
  - Backup safety: Zip extraction rejects paths outside target boundary,
    preventing Zip Slip / directory traversal vulnerabilities.
