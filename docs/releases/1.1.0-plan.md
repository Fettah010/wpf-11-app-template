## 1. Outcome and success definition

Make the `1.0.0` baseline trustworthy and repeatable before any feature work. Success = README/roadmap/deferred docs match the shipped `1.0.0`; no required UI test can pass by skip unnoticed; Clean/Recommended/Full generate, build, and smoke-test from both source folder and packed `.nupkg`; template validation is isolated (no global `dotnet new` corruption, no shared TEMP clobber); startup/perf scripts resolve outputs robustly; dependency/license/package inventory agrees; reproducible behavior defects get focused fixes + regression tests; `v1.0.0` tag/asset untouched (additive `1.1.0` release).

## 6. Design and architecture

- No product architecture change. Changes are confined to: docs (`README.md`, `AGENTS.md`, `DEFERRED.md`, roadmap status), test infra (`UiAutomation` summary/assertion, possibly a small helper), CI workflow (`ci.yml` matrix), eng scripts (`test-templates.ps1`, `measure-startup.ps1`), and focused bug fixes only where S09 reproduces a defect.
- Dependency boundary: zero new assemblies/packages. If the vuln audit forces a pin change, treat as patch-level with compatibility check + generated-consumer build.
- UI-test truth design: keep `UiEnabled()` local convenience; add a test-run summary sink (console + machine-readable e.g. TRX/console-token) and a gate script/CI step that parses executed vs skipped and fails the required job on unexpected skip. Exact mechanism chosen at implementation; plan constraint: required CI job red when required UI cases did not execute.
- Template isolation design: `DOTNET_CLI_HOME=$work/cli-home`, `dotnet new install` scoped to that hive; per-run stdout/stderr log files under the per-run GUID dir; `try/finally` uninstall + dir removal; never delete registrations outside the hive.
- Perf script design: mirror `smoke.ps1` dynamic `*App.exe` lookup under `src/` Release; on 0 or ≥2 ambiguous hits, fail with listing; keep `-Runs` median/max reporting.
