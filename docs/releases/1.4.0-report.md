## 3. Research and architecture decisions

- **Restart-apply (ADR-0015):** 15+ UI runs switching Sidebar→Top crashed
  intermittently (NaN `DoubleAnimation` during re-template). WPF-UI 4.3.0
  source confirms (`PaneOpen` animates `PaneGrid.Width` with
  `To="{TemplateBinding OpenPaneLength}"`); upstream PR #1012/#1015 fixed
  only the load path. Four mitigations exhausted with evidence (close-first
  + 500 ms settle; transitionless close + Width defuse with checkpoint
  tracing proving the crash precedes replacement; control recreation with
  unbind-first). Launching into any persisted shell never crashes. New
  `D25` tracks the upstream fix; revisit per toolkit upgrade.
- **Route registry over framework:** Dane-ME patterns evaluated as
  patterns-not-dependency; minimal registry + per-key independent opens
  solve the demonstrated gaps (a shared-CTS search-box design was replaced
  after proving it cancels independent documents).
- **Frame-per-tab:** WPF `Page` parents only to `Window`/`Frame`
  (Event-Log-proven crash); documents host pages in chromeless per-tab
  `Frame`s.
- **UI-thread marshaling:** hook continuations resume on threadpool;
  collection/selection/persistence rejoin the dispatcher (`RunOnUiThreadAsync`,
  direct-call fallback without `Application.Current` for tests).
- **Template token rule:** a literal `//#if` inside comments silently
  truncates generated files (proven: 13-line output); matrix asserts zero
  tokens; template guide documents the rule.
- **Drag prototype learning:** traced nested modal drags with stale sources
  (single-gesture guard added); traced sequential OLE cancels across runners
  (quiet CI included) led to deferral — the guard and private-format design
  are recorded here for the revisit, not shipped.
- **CI matrix slowness root cause (T13):** each generated-app build invoked
  through the harness's `Start-Process -Wait -RedirectStandardOutput` blocked
  ~15 min: lingering MSBuild nodes / the MSBuild server / the Roslyn
  `VBCSCompiler` inherited the redirected handle, so `-Wait` did not return
  until their idle timeout. Measured locally on the same build: **906 s vs
  10 s** once `MSBUILDDISABLENODEREUSE=1`, `DOTNET_CLI_USE_MSBUILD_SERVER=0`,
  and `UseSharedCompilation=false` are set (two blocked calls per combo =
  the observed ~30 min/combo, `2 h+` per job). The full source matrix now
  runs in **7.2 min** and the package matrix in **6.8 min**. Also fixed a real
  template defect the (previously unhit) Full+Tabbed smoke exposed:
  `SettingsServiceTests.ShellDefault_FallsBackToSidebar_InRepo` hardcoded
  `Sidebar` and shipped into apps generated with a non-Sidebar shell (MTP exit
  code 2); the assertion moved to repo-only `ScaffoldDefaultTests.cs`, excluded
  from `template.json` alongside the other repo-only guards.
- **Rejected:** ModernWPF stacking (no new need), docking suite (no
  consumer), Verify snapshots (license fee), custom top chrome (native Top
  proven working via restart path), tear-out/multi-window (no consumer).

**Drag gate outcome (AC05 → deferred gesture):** the automated drag test
failed on the focus-contested local desktop AND on the quiet CI runner with
order unchanged and no app crash. Traced runs show sequential OLE-cancelled
gestures (each intermediate move ends the in-flight drag with effect None;
the final drop moves a wrongly-sourced tab or no-ops); no product-side drop
defect was isolated, but the gate demands proven reliability, so the gesture
was removed before release and the reorder contract stays keyboard-operated
(Move buttons: unit + UI proven, deterministic). D14 records the deferral.
